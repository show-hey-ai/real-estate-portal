# Buyer journey autonomous improvement — 2026-10-05

The zero-paid-AI observation worker now measures and selects multilingual purchase consultation and registration copy. It uses the existing hourly `observe` job and its live lease. No new scheduler, paid API, schema migration, external messages or advertising spend is introduced.

## Product scope

The homepage consultation buttons, purchase criteria page title and WhatsApp button, and registration title/button compare two consistent visitor variants. Four languages are maintained. The original, area/budget, and approachable-consultation catalogs are reviewed declarative strings: no arbitrary generated HTML, destinations, registration requirements, prices or authorization changes. A manual copy change changes the fingerprint and disables this version until deliberately revalidated. A per-field manual change is also preserved by the client.

A signed HttpOnly cookie assigns a browser to the current experiment. Assignment persists across homepage, match and registration. Exposure means at least half the text became visible, not merely fetching the page. One browser counts once per experiment. Clicks and registration submissions are observed signals. A confirmed Supabase registration is counted only when a new, verified account was actually created after assignment. Authenticated outcomes deduplicate once per account per experiment using an anonymous keyed fingerprint, across tabs and devices. Displayed assignment IDs are checked against signed cookies on observed and confirmed events; mismatches are omitted. Email confirmation carries only this public assignment ID to the callback. Actual consultation is counted only after the authenticated buyer's lead or private chat message is persisted. Empty rooms and opening WhatsApp do not count as sent inquiries; WhatsApp has no delivery integration. No credentials, messages, email addresses, property addresses or entered purchase conditions enter this analytics dataset. Existing chat participant authorization is preserved.

UTM campaign identifiers (ASCII, max100 characters) on post links attribute the first observed exposure and subsequent conversion. Visits from different posts can be compared in the admin console; this does not automatically publish or rewrite social posts. The purchase-condition form currently prepares a WhatsApp message and does not persist a condition registration. Do not report form visits or WhatsApp clicks as completed condition registrations.

## Decision contract

A minimum14-day cohort needs200 exposed browsers per arm. Until then, collect and retain the incumbent. Once reached, enrollment closes once under the observation job's valid lease; existing assigned browsers retain their treatment for24 hours. New visitors see the incumbent without enrollment. Only after every outcome window has matured is one decision made, avoiding repeated hourly significance peeking.

Primary outcome: unique persisted buyer consultation within24 hours of first exposure. At least10 total consultations are needed. Candidate adoption requires non-overlapping99% Wilson intervals and at least1 percentage point absolute improvement. Clicks, submissions and registrations alone cannot select a winner. Inconclusive cohorts keep the incumbent. The next reviewed candidate then runs; after the catalog is exhausted the incumbent remains and no repeated significance tests are run on the same candidate. This is a conservative operational rule, not proof of revenue lift, payment completion, causal effects across all traffic sources or a guaranteed uplift.

The desktop agent may prepare new copy hypotheses from aggregate observations and public examples, with independent code review and regression checks, then deliberately roll a new fingerprint/experiment. The deployed system autonomously tests and adopts the available catalog; unlimited text generation and social publishing are not enabled.

## Operations and privacy

Private `autonomy_records` hold state, pseudonymous event records, aggregate decisions and observations. No direct public reads. Global autonomy stop, funnel stop and manual display override take precedence. Stop/manual changes start a fresh experiment identifier so mixed-treatment cohorts never select a winner. Record writes and state decisions serialize on the existing autonomy policy row; decisions also require the same revision and a valid observe lease. At20,000 cohort events the funnel is explicitly paused and an incomplete-cohort warning is saved; this prevents unlimited private-record growth and prevents truncated outcomes selecting a winner. Instance-local anonymous requests are limited to120 per IP per minute with at most5,000 buckets; streamed bodies are capped at1KiB before parsing. This is a bounded abuse control, not a distributed firewall. Staff, known crawlers and privacy opt-outs are excluded. Client conversion events are rejected. Analytics errors never break auth, inquiry or chat success.

Admin: `/admin/autonomy`, section「買主集客の自律改善」. It displays exposures, clicks, submissions, verified registrations, actual inquiries, campaign comparison and adoption history, and supports stopping or fixing a display manually. Configuration requires admin session, same origin and expected revision. Manual preferences are retained by worker iterations.

Initial state is created only if absent by the private activation script after a validated deployment. Changes preserve the existing zero-yen budget, publication settings, property visibility and source freshness. The existing local launch worker must be reloaded once after updating imported code. Activation is not evidence of improved conversion: real cohorts must accumulate first.

Vercel uses Supabase transaction pooling (6543 instead of session-mode5432) with at most2 connections per process and a1-second idle timeout. The Prisma7 pg adapter uses unnamed queries, and interactive transactions keep their client until commit. Local workers and migration URLs retain their existing connection mode. Trusted-CA verification remains enabled; invalid connection URLs produce sanitized errors without credentials.
