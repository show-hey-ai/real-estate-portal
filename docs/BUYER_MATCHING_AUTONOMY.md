# 継続する買主条件・評価・物件提案

`/match` は、本人の購入条件保存 → 公開物件との継続照合 → 評価 → 3件比較 → 物件別の専用チャットをつなぐ。条件は目的、価格帯、希望区、種別、時期、資金調達予定、現況、面積、築年、駅徒歩、表面利回り。日本語・英語・繁体字・簡体字の画面を提供する。

条件に一致、不一致、未確認を分ける。参考適合度は入力条件との比較であり、融資審査、購入資格、収益、入居可能日の判定ではない。購入諸費用、保有費用、引渡し、実収支、用途制限は、根拠が揃うまで未確認として示す。高評価した物件の地域・種別は順位と検索順へ反映できるが、保存済み予算や地域の指定は書き換えない。除外した候補の評価は保持し、新しい提案の上位30件だけを現行の世代として表示する。

## 自律更新とREINS

本人の表示時に再照合し、既存の `observe` ジョブでも、1時間以上未更新の有効な条件を古い順に最大10件処理する。公開在庫が1,000件を超える場合は処理不完全と記録する。全体停止・本人による停止は維持する。

既存の `reins_intake` ジョブは、運営設定の取得間隔を変えず、未処理の買主条件を古い順に1つ選ぶ。希望区と種別を順に巡回し、価格の単位を円から万円へ変換して既存ダウンローダへ渡す。価格の下限を別途強制しない。面積、築年、駅徒歩、利回り、資金調達や引渡しの未確認点は取得後の比較で扱う。1回の取得は検索1ページ・最大50資料ページの既存制限内とする。取得間隔が24時間なら、買主が多い場合には各買主への検索間隔も長くなる。画面に即時検索完了や全REINS在庫の調査済みとは表示しない。

買主検索では必要な検索入力や除外選択肢が見つからなければ取得失敗とする。取得中の条件変更・停止・削除、運営設定停止、lease失効は取得処理を停止する。削除後に同じ内容を再登録しても、古い取得処理を新しい条件の完了扱いにしない。

取得資料は既存の非公開領域へ保存し、原図面全頁・帯の広告条件、写真、物件同一性、鮮度を確認する。取得完了と掲載許可は別工程。0円のAI予算、無料のデスクトップ判断・OCR、公開前審査、ユーザー編集とソースoverrideを維持する。資料取得だけで公開・既存掲載期限延長をしない。

## 個人情報と整合性

保存条件と評価は `auth.users.id` に結び付く本人専用データ。メールアドレスの一致や管理者という役割だけでは読めない。ブラウザからのDB直接書込みを禁止し、同一オリジン・認証・厳格な入力検証を経たAPIだけを使う。編集・削除・評価にはプロフィールIDと版を検証し、評価再送はnonceで重複排除する。画面のログアウト・アカウント切替・読込競合では以前の個人情報や編集中の条件を混ぜない。

公開許可・広告承諾・公開種別・情報期限・現在の物件情報を毎回検査する。非公開住所、担当者連絡先、入居者情報、原PDFは返さない。条件と評価を物件管理者へ自動送信しない。通常の管理画面や自律運営の共有記録には件数と成功/未完了だけを残す。REINSには検証済みの物件検索条件だけを渡し、買主ID、資金調達予定、評価理由や自由文の操作指示を渡さない。

紹介はポータル内の提案として提供する。メール・WhatsApp・SNS・業者への自動送信、電子署名、決済は行わない。相談開始は買主が既存の物件別チャットを押した時に進む。

## 確認

`tests/buyer-matching*.test.ts` で条件、適合説明、検索計画、本人分離、RLS、競合、重複再送、削除と再作成、広告・鮮度・内容更新、提案世代、処理上限、取得中断を確認する。稼働時は `buyer_matching_observation` の集計と本人の `/match`、REINS取得記録を確認する。未完了、利用時間外、ログイン待ち、取得失敗を成功扱いにしない。テスト用の実環境確認はトランザクションをロールバックし、実顧客に架空の購入条件を登録しない。
