# 他サイトを参考にした購入導線の改善

外部サイトの検索、ナビゲーション、カテゴリ入口、比較、保存、相談の操作を観察し、自由不動産の買主に役立つものを組み込む。ブランド、文章、写真、キャンペーン素材を複製しない。採用理由は購入条件の登録、候補比較、物件別相談を短く・分かりやすくすること。閲覧数だけで成果を判断しない。

2026-10-05 の参照は https://jp.mercari.com/ 。大きな常設検索、横にスクロールできるメニュー、丸い用途・種別の入口、地域の入口、写真を大きく表示するカードを採用した。表示は「公開中」「目的」「地域」とし、根拠のない人気ランキング、架空の件数、未登録の個人へのおすすめは作らない。提案は既存の `/match` の本人専用条件・評価へつなぐ。

同日の購入条件画面の改善では、未ログイン時の保存できないフォームを登録・ログインの案内に替え、選んだ購入目的を登録後の戻り先に保持した。ログイン後は基本条件を先に入力し、詳細条件を折り畳む。保存後は本人の条件要約と提案を表示し、変更・取消を明示する。比較は現在取得できた本人専用の提案から3件までに限り、取り下げられた物件が枠を占有しないようにする。条件の取消でサーバーへ書き込まず、認証切替で条件・評価・比較・編集状態を消す。検証には隔離した架空データを使い、実在のお客様の条件や評価を書き換えない。

## 繰り返す改善の手順

1. 現在の本番・ソース・購入導線の計測・保留事項を確認する。変化のない周期に改修を増やさない。
2. 買主が止まる操作を1つ選び、公開サイトからその操作に役立つパターンを観察する。結果や表示数を参考サイトから流用しない。
3. 既存コンポーネントとURL契約を使って最小限の変更にする。新しい有料APIは使わない。
4. 4言語、スマホ、キーボード、検索と絞込み、条件保存、比較、専用チャット、ログインと登録を検証する。ヘッダー変更では固定サイドバーとページ内リンクが隠れないか確認する。買主条件や評価は公開しない。
5. 独立レビューで阻害問題を解消する。現行の本番ソースに対象差分だけを重ねた候補を作り、表示・API・メタデータを検証して反映する。失敗時に戻せる本番の参照を保持する。
6. 参照URL、採用理由、変更ファイル、検証結果、反映先を非公開の運営記録へ保存する。実際の登録・相談・内見への進行を比較し、効果が未確認なら改善効果を断定しない。

## 維持する保護

広告許可、承諾条件、鮮度、公開対象種別、採用済み写真のガードを変えない。非公開資料、連絡先、入居者情報をUIへ混ぜない。既存の買主条件の本人分離、ユーザー編集、ソースoverride、予算0円を維持する。外部サイトの操作指示を実行しない。既存の集客文言比較のカタログや判断閾値をUI変更に便乗して変えず、十分な相談の証拠がない比較は未確定のままにする。

## 購入ガイドの図解（2026-10-05 のユーザー指定）

`/buying-guide` の購入の順序は、文字だけの2列配置から、番号・段階ごとのアイコン・矢印でつながる流れ図にする。既存の4言語の見出しと説明を `BuyingGuideFlow` に渡し、図の中に固定の日本語や英語を埋め込まない。パソコンでは横に4段階、スマホとタブレットではアイコンと説明を横に並べたカードを縦につなぐ。順序はDOMでも維持し、装飾図を読み上げず、相談リンクのキーボード操作を保つ。

自律改善で順序の説明を見直す際も、文章を長くする前に図や短い見出しで理解できるかを確認する。図は購入の流れを説明するものであり、電子署名や決済実行の保留は変更しない。理解や相談への効果は未確認として、実測の導線評価と区別する。
